Sistemul de Trace (Cutia Neagră)

Butonul roșu [TRACE] (unde e prezent) rulează independent de restul aplicației și înregistrează pașii de pornire și erorile, permițând copierea log-ului chiar dacă interfața principală e blocată.

3. Ierarhia de Sortare (getCategory)

Aplicația decide coloana unui eveniment în această ordine strictă:

  1. Prefixe manuale de recurență: RL / R[n]L → LUNARE, RS / R[n]S → CURENTE, RA / R[n]A → ANUALE. n este intervalul opțional (ex. R2L = la fiecare 2 luni).
  2. Cuvinte cheie: "Sfânt", "Ortodox", "Catolic", "Nuntă", "Cununie", "Botez", "Adormirea", "Ziua" → ANUALE, indiferent de alți factori.
  3. Analiză RRULE reală (vezi secțiunea 4): dacă niciun prefix/cuvânt cheie nu se potrivește, se citește regula de recurență efectivă a evenimentului Google — MONTHLY → LUNARE, YEARLY → ANUALE.
  4. Implicit: dacă nimic nu se potrivește → CURENTE.
Eroare corectată în v41: anterior, câmpul recurrence era citit direct de pe aparițiile individuale (singleEvents=true), care nu conțin niciodată acest câmp — doar evenimentul-părinte îl are. Rezultatul era că pasul 3 (Analiză RRULE) nu funcționa niciodată, iar aplicația cădea mereu pe eticheta text (pas 1/2) sau pe implicit CURENTE. Vezi secțiunea 4 pentru soluție.

4. Cum se citește corect frecvența de repetare (RRULE)

Google Calendar nu stochează recurența ca text ("lunar", "săptămânal") ci ca regulă standardizată RFC 5545 (iCalendar), numită RRULE. Ca să deduci frecvența reală a unui eveniment, NU se ghicește din text — se parsează acest string.

4.1 De unde vine informația

Un eveniment recurent are un evenment "master" (părinte) care conține un array recurrence:

"recurrence": [
  "RRULE:FREQ=WEEKLY;INTERVAL=2;BYDAY=MO,WE;COUNT=10"
]

Instanțele individuale (obținute cu singleEvents=true, cum face Trident pentru afișarea pe zile) nu au acest câmp. În schimb au recurringEventId, care indică ID-ul evenimentului părinte. De aceea sincronizarea trebuie să fie duală: o dată pentru instanțe (afișare), o dată pentru masters (citire RRULE) — vezi tabelul din secțiunea 1.

4.2 Câmpurile relevante din RRULE

  • FREQ — unitatea de bază: DAILY, WEEKLY, MONTHLY, YEARLY.
  • INTERVAL — "la fiecare N unități" (implicit 1 dacă lipsește). Ex: FREQ=MONTHLY;INTERVAL=2 = la fiecare 2 luni.
  • BYDAY, BYMONTHDAY — rafinează în cadrul unității (ex. lu/mi din fiecare a doua săptămână).
  • COUNT / UNTIL — marchează finalul seriei; dacă lipsesc ambele, recurența e infinită.

4.3 Parsare (JavaScript, fără librării externe)

function parseRecurrence(recurrenceArray) {
  var rruleLine = recurrenceArray.filter(function(r){
    return r.indexOf('RRULE:') === 0;
  })[0];
  if (!rruleLine) return null;

  var params = new URLSearchParams(rruleLine.replace('RRULE:', '').replace(/;/g, '&'));
  return {
    freq: params.get('FREQ'),               // DAILY / WEEKLY / MONTHLY / YEARLY
    interval: parseInt(params.get('INTERVAL') || '1'),
    byDay: params.get('BYDAY') ? params.get('BYDAY').split(',') : null,
    count: params.get('COUNT'),
    until: params.get('UNTIL')
  };
}

4.4 Aplicat în Trident (v41)

Funcția syncGoogle() face acum doi pași: descarcă instanțele lunii (pentru grilă) și, separat, evenimentele master din același interval (pentru RRULE). Construiește o hartă id_master → RRULE, iar pentru fiecare instanță afișată caută RRULE-ul real fie pe eveniment (dacă e el însuși master), fie prin recurringEventId în hartă. Rezultatul e pasat lui getCategory(), care aplică MONTHLY→LUNARE / YEARLY→ANUALE corect, ca ultim nivel din ierarhie.

4.5 Creare de recurență reală (nu doar etichetă)

Comenzile cu prefix R (ex. 15RLGaz) nu mai creează doar o intrare locală pentru luna curentă cu eticheta de coloană forțată — creează un eveniment cu recurrence: ["RRULE:FREQ=...;INTERVAL=..."] trimis direct către Google Calendar (dacă există sesiune activă), astfel încât apare automat, prin sincronizare normală, în toate lunile/săptămânile/anii viitoare. Offline, se folosește o recurență locală echivalentă, expandată de aplicație la randare.
